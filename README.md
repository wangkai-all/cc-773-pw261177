# 调和参谋 · 罐区混料分析

一个从零搭建的混料分析应用：在**成分只有检测区间**的前提下，求「在给定不确定范围内仍满足质量要求」的最低成本配比，并区分**独立检测误差**与**同批共同偏移**；同时处理罐中余量、已确认订单的库存竞争，以及两人同时确认方案时的乐观并发控制。

> ⚠️ 本仓库中的所有原料、库存、检测值、规格与成本**全部是虚构数据**，仅用于演示鲁棒优化与并发控制。
> **不连接任何真实生产设备、DCS、LIMS 或生产数据库**，也不读写任何真实生产文件。

```bash

npm start              # 生产模式：http://localhost:8787
```


## 2. 领域模型

### 2.1 罐区与规格

- **8 罐新鲜原料**（重整生成油、催化裂化汽油、烷基化油、MTBE、甲苯、轻石脑油），每罐有库存量、到厂成本（元/t）与五个指标的检测区间：
  RON（研究法辛烷值）、S（硫，mg/kg）、D（20℃密度，kg/m³）、BZ（苯，%v）、OLE（烯烃，%v）。
- **罐底余量（heel）** 140 t 视为**独立批次**，计入产品总量但不参与决策。它的成分同样只有区间，因此它自身也贡献不确定因子。
- 产品规格（`shared/fixtures.ts`）：
  - `SPEC-92`：1000 t，RON ≥ 95.5、S ≤ 9、密度 720–775、苯 ≤ 0.8、烯烃 ≤ 18。
  - `SPEC-95`：更严的 RON ≥ 97 与 S ≤ 6，用于演示同罐区两个牌号争夺同一批原料。
  - `SPEC-IMPOSSIBLE`：S ≤ 2，故意超出所有可用原料的能力范围，用于演示不可行诊断。
- 检测区间：`nominal ± halfWidth`。**缺检测**（`hasAssay: false`）的罐不会被当作 0，而是从需要该指标的牌号候选集中剔除，并在结果中列出原因。

质量口径（演示用线性化）：各指标按**质量加权**混合：`指标总量 = Σ 罐量 × 检测中心值 + 余量 × 余量中心值`，再除以产品总量。密度同样按线性化处理，属于演示近似。

### 2.2 不确定因子：独立误差 vs 共同偏移

每个指标每类误差建模为一个因子 `ξ ∈ [−1, 1]`：

```
指标总量偏移 = Σ_f c_f(配比) · ξ_f
```

- **独立因子** `I|lot|property`：每个罐一套，系数 `(1−ρ) × halfWidth × 该罐投入量`。
- **共同因子** `S|batch|property`：**同批次的所有罐共用一个 ξ**，系数 `ρ × halfWidth_lot × 该罐投入量` 在批内**叠加到同一个 ξ 上**。
- 罐底余量按自己的批次 `G-HEEL` 处理：`ρ<1` 时有一个独立因子，`ρ>0` 时有一个共同因子（常数项而非按投料量缩放）。

ρ ∈ [0, 1] 是「同批共同偏移占检测误差的比例」，可在界面调节（建模参数，不改变库存，因此**不推进版本号**）：

- ρ = 0：误差全部独立，同批两罐的误差可以互相抵消。
- ρ = 1：误差全部同批共因，同批两罐**必定同向**偏移。
- 默认 ρ = 0.6。

### 2.3 为什么不能把所有上限直接相加

如果对每个罐、每个指标都按 `nominal ± halfWidth` 取最坏再相加，得到的是**箱式最坏**（每个因子同时取到端点），其发生概率为 `2^(−因子数)`。本示例 SPEC-92 下有 70 个因子，同时取端点的概率约为 `8.5 × 10⁻²²`——这个事件实际上不可能发生。

本项目提供三档「可共同发生」的保守程度，并用显式场景集量化风险：

| 模式 | 保护范围 | 说明 |
| --- | --- | --- |
| `nominal` | 只用检测中心值 | 最便宜，但实际偏移下会超限（见下） |
| `box` | 所有因子同时取 ±1 | 等价于「逐项上限相加」，最保守 |
| `budget(Γ)` | `{ξ : Σ\|ξ_f\| ≤ Γ, \|ξ_f\| ≤ 1}` | Bertsimas–Sim 预算不确定集：最多有「Γ 个因子当量」同时偏离 |
| `chance(α)` | 显式离散场景集上的满足概率 ≥ α | MILP：每个场景配一个 0/1 变量，违反场景的概率之和 ≤ 1−α |

**预算模式的最坏值**不是把上限相加，而是取系数最大的前 ⌊Γ⌋ 个因子取端点、第 ⌊Γ⌋+1 个取 `Γ−⌊Γ⌋` 份额（`shared/uncertainty.ts::budgetDeviationTotal`，即 `sumLargest`）。Γ=0 退化为名义方案，Γ 足够大时等于箱式。

**场景集**（`buildScenarioSet`，固定种子 20261124，BASE 数据下共 47 个场景）是显式离散分布，权重归一化后总和严格为 1，包含：

- 1 个名义场景；
- 箱式上下角点、全批共同偏移 ±1、单指标整体偏正/偏负、前两个批次整体偏正/偏负、前四罐单罐离群 ±1 等压力场景；
- 20 个均匀抽样场景（原始权重合计 72%）。

各类场景的原始权重为：名义 0.16、箱式角点 0.002、全批共同偏移 0.01、单指标 0.008、批次 0.006、单罐 0.004、均匀抽样共 0.72；总和为 1.04，归一化后名义场景约占 15.4%、箱式角点各约 0.19%。场景权重是演示设定，不代表真实概率，但归一化后的数值会被严格用于 α 约束与风险统计。

求解后会报告：**场景满足概率、每个指标的违反概率、实际最坏违反场景**（含场景标签、概率、超限指标与超出量）。

### 2.4 实际效果（虚构 BASE 数据，SPEC-92，ρ=0.6）

| 方案 | 总成本（元） | 元/t | 场景满足率 |
| --- | ---: | ---: | ---: |
| 名义 | 5,665,478 | 5,665.5 | 39.6% |
| 预算 Γ=2 | 5,682,151 | 5,682.2 | 92.1% |
| 预算 Γ=4 | 5,690,374 | 5,690.4 | 97.1% |
| 场景 α=90% | 5,676,085 | 5,676.1 | 91.0% |
| 箱式最坏 | 5,704,802 | 5,704.8 | 100% |

名义方案只比预算方案便宜约 1.7 万元（0.3%），但在场景集上只有不到四成满足——它把硫、RON 的余量用到了检测中心值的极限，一有偏移就超限。这正是「只看名义值」的危险所在；箱式方案虽 100% 满足，却要多付约 4 万元。预算/概率方案给出了可解释的中间选择。

## 3. 优化模型

对每个候选罐 `l` 设投入量 `x_l ≥ 0`（上界为当前**可用量**）：

```
min  Σ cost_l · x_l
s.t. Σ x_l = 产品总量 − 罐底余量
     对每个指标每个方向：
       nominal：  sign · (Σ nominal_l · x_l + heel·q_heel) ≤ sign · limit · volume
       box：      同上，系数改为 nominal_l + sign·halfWidth_l，余量项也加 halfWidth
       budget：   上述名义约束 + 辅助变量 λ 与 p：
                    sign·Σ nominal_l·x_l + Γ·λ + Σ p_f ≤ rhs
                    p_f + λ ≥  c_f(配比)       （c_f 为因子系数，含余量常数项）
                    p_f + λ ≥ −c_f(配比)
       chance：   名义约束 + 每个场景每个方向的行： sign·(nominal + 场景偏移)x − M·y_s ≤ rhs
                  Σ prob_s · y_s ≤ 1 − α        （y_s 为 0/1）
```

求解器是 HiGHS（WASM，npm `highs`），LP 以 CPLEX-LP 文本格式构建（`shared/lp.ts`），全程在服务端运行，前端不加载 wasm。

求解后还会给出：

- **保证值 / 名义值**：按模式的最不利方向计算（箱式/预算用解析最坏，概率模式用场景集最差）。
- **受限指标与影子价格**：把每个限额向宽松方向移动 0.1 个指标单位后重解，报告总成本变化（正=放宽可降本）；对方案实际用到的每个罐做 +10 t 可用量的重解，报告增量价值（概率模式不做此项重解）。
- **不可行诊断**：先测「完全不考虑其它指标」的能力极限（真短板），再把不可行指标从约束中剔除，检查其余指标之间是否还有冲突。因此不会因为一个指标不可行就给所有指标同时报警。若可用新鲜原料总量不足，直接给出缺口与「释放未投料预留」的建议。
- **缺检测说明**：列出被排除的罐及缺失指标。

## 4. 并发确认与库存

### 4.1 库存占用

- 确认方案 → 生成订单与一组 `active` 预留，`可用量 = 库存 − active 预留 − committed 预留`。
- **释放未投料**：把该订单所有 `active` 预留置为 `released`，可用量恢复。
- **标记投料**：把 `active` 置为 `committed`，此后**不可释放**。
- 状态版本号 `version` 只在**影响可用量/检测区间**的变化时前进：确认、释放、投料、编辑检测区间、切换样例。**生成草稿方案与修改 ρ 不推进版本**——否则两位操作员永远无法共享同一基线。

### 4.2 两人同时确认，只有一个成功

1. 甲、乙各自基于当前版本 `v` 求解，得到两张草稿方案（都不占用库存）。
2. 甲先确认：`clientVersion = v` 与服务端一致 → 成功，预留写入，版本变为 `v+1`。
3. 乙再确认：`clientVersion = v ≠ v+1` → HTTP 409，返回
   「方案基于版本 v，但库存已变化（当前 v+1）。请重新求解后再确认。」
4. 乙重新求解后拿到新版本，才可能确认成功。

确认前服务端还会：

- 校验提交的配比与求解结果逐罐一致（容差 0.05 t）；
- 校验配比总量等于所需新鲜量；
- 按**当前**可用量重新检查每个罐是否够用；
- 已在同一张单上重复确认 → 409；同一 `Idempotency-Key` 重放 → 返回首次的预留结果（不会重复扣减）。

界面右下角的「并发演示」面板内置两位操作员，可一键「两人各自求解」「同时确认两张单」「失败方重新求解」，直接观察 409 与重解流程。`tests/store.test.ts` 对这组语义有 7 个测试。

## 5. 小规模枚举核对

「求解器说的最优/最坏」可以在界面上用独立枚举复核（结果区「枚举核对」页，`POST /api/verify`）：

### 5.1 配比枚举 vs LP 最优

- 把新鲜量按固定步长切成整数份（步长自动选择，保证步长**整除**新鲜量，且组合数 ≤ 40 万；组合数用动态规划 `countCompositions` 预估，避免静默截断）。
- 在库存上限内穷举所有分配，计算名义成本、名义可行性、以及所选保护模式（名义/箱式/预算）下的最坏指标。
- 结果给出：组合数、名义可行/保护可行数量、**离散最优成本**与 LP 最优的差额。
- 正确性判据：连续 LP 是离散网格的松弛，**离散最优不可能比 LP 更便宜**；若出现更便宜，界面会标红提示「LP 遗漏了离散点」。

### 5.2 因子顶点枚举 vs 解析最坏

- 对每个指标，取系数幅度最大的前 5 个因子：
  - 箱式：枚举全部 `2^n` 个 ±1 顶点；
  - 预算：枚举多面体 `{Σ|ξ| ≤ Γ, |ξ| ≤ 1}` 的顶点（⌊Γ⌋ 个坐标取 ±1，余下分额给一个坐标取 ±(Γ−⌊Γ⌋)）。
- 把枚举极值与解析最坏值逐项比较：**解析值必须 ≤ 枚举极值**（`match`）；未截断时两者应完全相等。
- 表中同时列出「全集解析」（全部因子）与「子集解析」（前 5 个因子），说明被截断的较小因子带来的差异。
- `tests/solver.test.ts` 与 `tests/enumerate.test.ts` 覆盖了 Γ=0、1、1.4、2、2.5、4 等情形，以及「箱式总偏移 ≤ 各自上界相加且严格更小」这条核心性质。

## 7. HTTP 接口

所有请求/响应均为 JSON（`application/json; charset=utf-8`）。操作员名通过 `x-operator` 头传递（前端做百分号编码，服务端解码），仅在审计与订单中展示。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 罐区状态（含版本、可用量、订单、预留、审计） |
| POST | `/api/solve` | 求解：`{specSetId, mode, rho, lotOverrides?, excludePlanId?}`，返回结果与方案 id |
| POST | `/api/plans/:id/confirm` | 确认：`{clientVersion}` + `Idempotency-Key` 头；成功返回订单与预留，冲突返回 409 |
| GET | `/api/orders` | 订单列表 |
| POST | `/api/orders/:id/release` | 释放未投料预留 |
| POST | `/api/orders/:id/commit` | 标记投料（此后不可释放） |
| POST | `/api/assay` | 编辑检测区间：`{lotId, property, cell}`，推进版本并审计 |
| POST | `/api/rho` | 调整 ρ（不推进版本） |
| POST | `/api/reset` | 切换虚构样例：`{fixture}` |
| GET | `/api/scenarios?specSetId=` | 当前 ρ 与库存下的显式场景集 |
| GET | `/api/fixtures` | 样例列表 |
| POST | `/api/verify` | 枚举核对：`{planId, gridStep?}`，返回顶点核对与配比枚举 |

求解结果缓存在服务端内存（最近 40 个方案），用于确认时校验配比与核对时重建因子。服务重启后旧方案需重新求解。

## 9. 测试覆盖要点

- 成本单调：名义 ≤ 预算(Γ) ≤ 箱式；Γ 越大成本不降、场景风险不升；α 越大成本不降。
- 名义方案在场景集上**确实**违反，并能指出实际最坏违反场景；箱式方案不违反。
- ρ=1 时同批罐的最坏幅度大于 ρ=0；同批共同偏移**只算一次**，箱式总偏移严格小于「各自上界相加」。
- 缺检测的罐被排除；不可行规格给出可定位的短差原因；余量计入总量并影响质量；可用量减少后重解成本上升或不可行。
- 并发：两张同基线草稿只有一张能确认；草稿不推进版本；重复确认 409；幂等键重放；预留扣减与排除自己；投料后不可释放；检测编辑推进版本；ρ 不推进版本。
- 枚举：组合计数与暴力一致；步长整除新鲜量；离散最优不优于 LP；保护越强可行组合越少、成本越高；Γ=0 与名义一致；缺检测不进入枚举候选。
